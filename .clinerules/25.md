# Cross-Platform Shell Command Safety

## 1. Detect the Active Shell and Operating System

Before executing a shell command, determine the actual execution environment.

For this repository, assume Windows compatibility is required unless the active environment is explicitly confirmed to be Linux/macOS.

Do NOT assume that Unix commands are available on Windows.

Common Windows environments include:

- PowerShell
- CMD
- Git Bash
- WSL

The command syntax must match the actual shell being used.

## 2. Do Not Use Unix-Only Commands in Windows CMD or PowerShell

When running under Windows CMD or PowerShell, do NOT blindly use Unix-specific commands such as:

- head
- tail
- grep
- sed
- awk
- cut
- xargs
- find
- which
- pwd
- rm
- cp
- mv

unless their availability has been explicitly verified.

A command that works in Linux/macOS may fail under Windows.

## 3. Windows Alternatives

Prefer native commands or Python when working under Windows.

Examples:

Instead of:

find . -type f -name "*.py" | head -50

Prefer PowerShell:

Get-ChildItem -Recurse -File -Filter *.py | Select-Object -First 50

Or use Python:

python -c "from pathlib import Path; print('\n'.join(str(p) for p in list(Path('.').rglob('*.py'))[:50]))"

For simple repository inspection, prefer the project-native tooling when available.

## 4. Prefer Python for Cross-Platform File Discovery

When shell compatibility is uncertain, prefer Python's standard library for repository inspection.

Example:

python -c "from pathlib import Path; print('\n'.join(str(p) for p in list(Path('.').rglob('*.py'))[:50]))"

For complex discovery, create a temporary or dedicated Python script instead of constructing a complex shell pipeline.

## 5. PowerShell Is Not Bash

Do NOT assume that PowerShell understands Unix pipelines or commands.

For example, this is NOT portable:

find . -type f -name "*.py" | head -50

The presence of a pipe character does not make a command cross-platform.

PowerShell has its own commands and pipeline semantics.

Prefer:

Get-ChildItem -Recurse -File -Filter *.py | Select-Object -First 50

when PowerShell is confirmed.

## 6. CMD Is Not PowerShell

Do NOT assume PowerShell commands work in CMD.

For example:

Get-ChildItem
Select-Object

are not CMD commands.

If the active shell is CMD, use CMD-compatible syntax or use Python.

When shell identity is uncertain, Python is generally the safer cross-platform fallback.

## 7. Do Not Chain Environment-Specific Commands Blindly

Avoid commands such as:

cd "C:\path" && find . -type f | head -50

unless every command in the chain is confirmed to exist in the active shell.

A valid Windows path does NOT imply that the remaining command is Windows-compatible.

Validate the complete command chain before execution.

## 8. Repository Inspection Priority

For repository inspection, prefer this order:

1. Existing project-native tooling.
2. IDE/editor search facilities when available.
3. Python standard library.
4. Confirmed PowerShell commands.
5. Confirmed CMD commands.
6. Unix commands only when running in a confirmed Unix-compatible shell.

Do not introduce a Unix pipeline merely because it is shorter.

## 9. Detect Command Failures Before Changing Code

If an error such as:

'head' is not recognized as an internal or external command

occurs:

classify it as:

COMMAND_ENVIRONMENT_ERROR

or:

SHELL_COMPATIBILITY_ERROR

Do NOT classify it as:

ACTUAL_CODE_FAILURE

Do NOT modify application/source code.

Replace the incompatible command with an environment-compatible equivalent and rerun the inspection.

## 10. Never Install Tools Just to Replace a Simple Command

If a Unix utility is unavailable on Windows:

Do NOT immediately install additional packages or command-line tools merely to provide:

head
grep
find
sed
awk
tail

Prefer existing PowerShell commands or Python standard-library functionality.

Avoid changing the development environment when the task can be completed with tools already available.

## 11. File Discovery Safety

When searching for files, prefer explicit and deterministic methods.

PowerShell example:

Get-ChildItem -Recurse -File -Filter *.py

Limit results when necessary:

Get-ChildItem -Recurse -File -Filter *.py | Select-Object -First 50

Python example:

from pathlib import Path
files = list(Path(".").rglob("*.py"))
for path in files[:50]:
    print(path)

Do not rely on Unix-specific command combinations in Windows environments.

## 12. Shell Command Verification

Before executing a non-trivial command:

1. Identify the shell.
2. Identify the operating system.
3. Check whether each command exists in that shell.
4. Check quoting rules.
5. Check path syntax.
6. Check pipeline syntax.
7. Execute only after compatibility is established.

If shell identity is uncertain:

STOP.

Use a cross-platform Python alternative or determine the active shell first.

## 13. Cross-Platform Project Rule

The application code may be cross-platform even when the development shell is not.

Do not introduce shell-specific assumptions into:
- scripts;
- tests;
- documentation;
- automation;
- CI;
- verification procedures.

If a shell-specific command is required, clearly identify the shell it requires.

## 14. Interaction With Existing Rules

This rule works together with:

- command execution safety;
- Windows command and script safety;
- encoding safety;
- failure triage;
- source-of-truth;
- forensic engineering;
- test strategy.

A shell compatibility failure must be diagnosed before any source-code modification.

## 15. Required Default

When operating on Windows:

- do not assume Unix commands exist;
- do not use `head`, `grep`, `find`, `sed`, `awk`, or similar Unix utilities without confirming availability;
- prefer PowerShell-native commands when PowerShell is confirmed;
- prefer Python when shell identity is uncertain;
- never modify production code because a shell command is unavailable;
- classify shell incompatibility separately from application failure.

For the specific pattern:

cd "C:\Users\Nguyen Cong Thong\Desktop\AI attendance" && find . -type f -name "*.py" | head -50

DO NOT execute it under Windows CMD or PowerShell.

Use an environment-compatible equivalent instead.

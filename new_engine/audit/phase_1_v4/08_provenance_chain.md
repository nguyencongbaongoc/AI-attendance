## 2. Deterministic ID Generation

### CrossingEvent ID
```
CE-{track_id}-{frame_index}-{timestamp_ms}
```
Or (Phase 22):
```
CE-{prefix}-{md5(camera_id:track_id:frame_index:geometry_config_hash)}
```

### RawInOutEvent ID (Phase 23)
```
RIE-{sha256(camera_id:local_track_id:source_crossing_event_id:geometry_version:geometry_config_hash)[:16]}
```

### ResolvedTransition ID (Phase 24)
```
RES-{sha256(camera_id:local_track_id:source_raw_event_id:resolver_version:resolver_config_hash)[:16]}
```

### AttendanceRecord ID (Phase 25)
```
Generated by AttendanceRepository (UUID or similar)
```

## 3. Timestamp Synchronization

### Timestamp Fields
| Field | Source | Clock |
|-------|--------|-------|
| `capture_timestamp` | RTSP packet receive | Wall-clock |
| `processing_timestamp` | AI inference complete | Wall-clock |
| `crossing_timestamp` | Frame timestamp | Wall-clock |
| `pts` | RTSP packet | Stream clock (90kHz) |
| `time_base` | RTSP stream | 1/90000 |

### Synchronization Notes
- **RTSP PTS ≠ Wall-clock**: PTS is stream-relative, not absolute
- **capture_timestamp**: Best approximation of frame capture time
- **stream_epoch**: Increments on reconnect, enables ordering across reconnects
- **frame_sequence**: Monotonic per stream_epoch
